## 二、组件详细说明

### 2.1 数据采集层组件

| 组件 | 类型 | 规格 | 说明 |
|------|------|------|------|
| **Kafka Cluster** | 消息队列 | 3 Broker | 高吞吐量日志摄入，支持多数据源 |
| **Zookeeper** | 协调服务 | 3 节点 | Kafka 集群协调 |
| **Kafka Connect** | 连接器 | 分布式 | 数据源集成 (S3, Database, etc.) |
| **Filebeat** | 代理 | 轻量级 | 日志文件采集 |
| **Syslog Agent** | 代理 | 轻量级 | Syslog/UDP/TCP 采集 |

### 2.2 流处理层组件 (Flink)

| 组件 | Job 类型 | 并行度 | 功能说明 |
|------|----------|--------|----------|
| **Log Parser Job** | DataStream | 4 | 日志解析、字段提取、数据富化 |
| **Alert Engine Job** | DataStream + CEP | 4 | 实时告警检测、规则匹配 |
| **Metrics Job** | DataStream | 2 | 指标聚合、统计计算 |

**为什么选择 Flink 而非 Python 多线程：**

| 对比项 | Python 多线程 | Flink |
|--------|--------------|-------|
| 吞吐量 | ~10K msg/s | 100K+ msg/s |
| 延迟 | 100-500ms | <10ms |
| 状态管理 | 需自行实现 | 内置 RocksDB |
| 容错 | 手动 | Checkpoint + Exactly-Once |
| 扩展性 | 有限 | 水平扩展 |
| 规则复杂度 | 简单 | 支持 CEP/时序/关联 |

### 2.3 存储层组件

| 组件 | 用途 | 特点 |
|------|------|------|
| **PostgreSQL** | 配置存储 | 用户、规则、资产、数据源配置 |
| **TimescaleDB** | 时序数据 | 时序分区、压缩、**全文搜索** |
| **Redis** | 缓存 | 热数据缓存、会话、限流 |

> **简化设计**: 使用 TimescaleDB (PostgreSQL 扩展) 统一存储时序数据，通过 `tsvector` 支持全文搜索，不再依赖 ClickHouse 和 Elasticsearch。

## 四、Flink 告警引擎设计

### 4.1 告警类型支持

```
┌─────────────────────────────────────────────────────────────────┐
│                     告警引擎支持的规则类型                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. 单事件规则 (Single Event)                                    │
│     └── 条件匹配 → 立即触发                                      │
│     示例: src_ip == "192.168.1.100" AND action == "login_fail" │
│                                                                  │
│  2. 关联规则 (Correlation)                                       │
│     └── 多事件关联分析                                           │
│     示例: user_id 相同的登录失败次数 >= 5 (任意 IP)              │
│                                                                  │
│  3. 时序规则 (Sequence/CEP)                                     │
│     └── 事件序列模式匹配                                         │
│     示例: [A 事件] → (5分钟内) → [B 事件]                       │
│                                                                  │
│  4. 阈值规则 (Threshold)                                        │
│     └── 滑动窗口聚合后触发                                       │
│     示例: 5分钟内的请求数 > 1000                                 │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 Flink CEP 示例

```java
// 时序规则: 暴力破解检测
Pattern<LoginEvent, LoginEvent> bruteForcePattern = Pattern
    .<LoginEvent>begin("failed")
    .where(e -> e.getAction().equals("login_fail"))
    .next("success")
    .where(e -> e.getAction().equals("login_success"))
    .within(Time.minutes(5));

// 关联规则: 同用户多IP登录
Pattern<LoginEvent, LoginEvent> multiIpPattern = Pattern
    .<LoginEvent>begin("first")
    .where(e -> e.getUserId().equals(userId))
    .followedBy("second")
    .where(e -> e.getUserId().equals(userId))
    .where(e -> !e.getIp().equals(first.getIp()))
    .within(Time.minutes(10));
```
